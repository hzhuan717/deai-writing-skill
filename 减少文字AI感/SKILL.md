# 减少文字AI感（中文学术论文句子级修复）

去掉中文学术论文里"一看就是AI写的"句子习惯。只改表达，不改论点，不编造事实。

与配套技能的分工：`减少AI痕迹` 管通用模式库，`减少防御性写作` 管叙事立场，本技能管**中文学术文本的句子级落地修复 + 量化验证**。三者可叠加使用。

## 先量化，再动手

AI 腔是密度问题，不是有无问题。动手前先统计（对 docx 用 python-docx 提取正文，不含参考文献和表格）：

```python
import re
body = '\n'.join(正文段落)
print('冒号：', body.count('：'))
print('分号；', body.count('；'))
print('双破折号——', body.count('——'))
print('单破折号—', body.count('—') - body.count('——')*2)
hedges = ['不作','不能','无法','仅','只能','不足','缺乏','难以','可能',
          '并未','不等于','并非','仍属','未经','缺少','有限','超出']
print('对冲措辞', sum(body.count(w) for w in hedges),
      '每千字', round(sum(body.count(w) for w in hedges)/len(body)*1000, 1))
```

参考阈值（1.5–2 万字论文正文）：

| 指标 | AI 感偏重 | 修复目标 |
|---|---|---|
| 冒号（ prose 部分） | > 35 | < 20 |
| 对冲措辞密度 | > 4/千字 | < 3.5/千字 |
| 行文内双破折号 | > 0 | 0（术语和副标题除外） |

## 六类文字层 AI 痕迹与修法

### 1. 冒号解说句（最强信号）

**模式**：判断句 + 冒号 + 分项解说。"X 并非全新事物：A 如何，B 如何。"一个冒号就是一次"我来给你解释一下"的腔调。几十个冒号堆起来，机器味扑面而来。

**修法**：不是删标点，是把解说句拆成两个独立的陈述句。

```
原：双主审并非全新事物：湖南、广州、淮北等地已持续开展实践。
改：双主审并非全新事物。湖南、广州、淮北等地已持续开展实践。

原：审计证据应当具有适当性和充分性：适当性衡量相关性与可靠性，充分性衡量数量。
改：审计证据应当具有适当性和充分性，前者衡量相关性与可靠性，后者衡量数量。
```

**保留的冒号**：引语前（"材料原文是：……"）、定义列举前（"按四档标注：'明确'指……"）、"三个问题：第一……"这类正式列举。改的是"判断+冒号+解释"，不是见冒号就删。

### 2. 对冲措辞与重复设防

**模式**：不作/不能/无法/仅/只能/不足/并非/可能……单看每句都"严谨"，密度一高就是心虚。更典型的是**同一道防线反复设**：摘要、绪论、文献述评、资料说明、分析章节、结论，每个部分都在声明"材料有限/不作因果断言/不作反向推断"。读者读到第三遍，感受从严谨变成不自信。

**修法**：防线只设一道。

- 边界声明集中放在两处：资料与方法部分的"判断边界"小节 + 结论的"研究局限"小节。其余位置全部删除或改写。
- 否定句改肯定句：

```
原：本文不作效能层面的因果断言。
改：本文考察流程接口层面的协同机理，效能层面的因果检验留待后续研究。

原：HN-1和HB-1未披露载体形态，不作反向推断。
改：（直接删除，事实陈述已经够了）
```

- 局限部分条目化压缩，每条一句话，不自责：

```
原：公开案例全部来自审计机关的自我报道，属于行为主体的自我呈现，较少披露
    冲突、误报、返工和统一口径的工时数据；四个案例的层级不完全一致……
改：本文存在三点局限。第一，案例全部来自审计机关的公开报道，冲突、误报、
    返工和工时数据较少披露。第二，四个案例层级不完全一致，编码由单人完成。
    第三，缺少单主审项目作为对照。
```

**注意**：假设性分析章节（如"潜在约束""风险推演"）里的"可能"是题中应有之义，不在清理范围。清理的是贯穿全文的免责声明。

### 3. 破折号与分号长句

- 行文内的双破折号（"X 是单向的——Y 从 A 流向 B"）改为逗号或句号，目标为零。
- **术语内的连接号保留**：如"交换—转译—衔接—反馈"这类自造术语里的短横是构词成分，不算 AI 腔。论文副标题的"——"是排版惯例，也保留。
- 分号串联的超长并列句拆成短句。中文论文一句一个意思。

### 4. 文学腔与比喻残留

AI 喜欢在学术文本里撒文学调料，人工作者很少这么写：

| 残留 | 改为 |
|---|---|
| 材料原文的措辞值得停留 | 材料原文写道 |
| 该约束的现实注脚 | 该约束的实际体现 |
| 因而一目了然 | 可以清楚辨认 |
| 链条在"核查—反馈"处断开 / 反馈回路被牺牲 | 核查结果不再返回分析环节 |
| 值得注意的是（每节都用） | 全篇至多保留一处 |

### 5. 自我设限定义重复

同一个限定性定义（如"'改进路径'指机制性、过程性的协同改进安排"）在摘要、绪论、改进章、结论里重复三四次。留一次，放在首次定义的章节（通常是绪论或概念章），其余位置删除。

### 6. 贡献表述虚化

"研究贡献"写成两段虚话、全文找不到"创新点"三个字，等于把送分题放弃。改成显性条目：

```
本文的创新点体现在三个方面。第一，……提供了可分析的机理框架。
第二，引入……视角，指出……。第三，区分了……两条回路，为后续研究提供了具体的观察内容。
```

配套判断：每个创新点都要能回答"文献里有没有人已经这样说过"。概念借用（如"转译"来自 Carlile）不妨碍组合创新成立，但表述只说"创新性概括/机制分析"，不吹"理论创新"。自造术语命名一篇论文 1–2 个足够，全起名像营销。

##  docx 论文修改的工程要点

用 python-docx 批量修改中文论文时：

1. **上标引用会被段落级重写破坏**。中文学位论文的 `[1-2]` 类引用通常是上标 run。重建段落文本时必须按引用正则切分并恢复上标：
   ```python
   CITE = re.compile(r'(\[(?:\d+(?:-\d+)?)(?:\s*,\s*\d+(?:-\d+)?)*\])')
   for part in CITE.split(text):          # 带捕获组！不带捕获组的split会丢弃引用
       run = p.add_run(part)
       if CITE.fullmatch(part):
           run.font.superscript = True
   ```
   教训：`re.split` 不带捕获组会**静默丢弃所有引用编号**，改完务必统计上标 run 数前后对比。
2. **删参考文献要联动重编号**。删除中间条目后，正文和表格里所有更大的编号都要前移；用正则解析编号区间（`[31-32]`、`[4,7-9,29]`）统一映射，别手工数。改完验证：文献编号连续、正文引用最大值等于条目数、每条文献都被引用。
3. **别动原文档**。新版本另存（第十一版→第十二版），符合作者的多版本习惯。
4. 目录是域代码，页码改动后在 Word 里 F9 刷新，不要在脚本里改目录文本。

## 收尾验证

改完重跑一遍开头的统计脚本，对比修改前后：

- 冒号、双破折号、对冲措辞密度是否达标；
- 抽查每个重写段落，确认论点没变、引用编号正确、上标还在；
- 朗读摘要和结论各一遍，凡是自己都解释不清的绕句（"构成……赖以发生的……"这类双重嵌套），要么改写到能脱稿讲清，要么删掉——答辩时老师专抓这种句子。
